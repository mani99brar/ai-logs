PRD: Classic Folder Cards

 Status

 Agreed scope, ready for implementation planning.

 Goal

 Replace the existing Markdown file table with a familiar folder browser. Users navigate Pi and Claude fixture directories through a unified grid of folder and file cards.

 Project context

 - React, Vite, and TypeScript frontend.
 - Fastify and TypeScript backend.
 - The existing GET /api/files endpoint lists fixture Markdown filenames.
 - Sources are fixtures/pi/ and fixtures/claude/.
 - This implementation is read-only: discover names and directories without reading document contents.

 Scope

 ### Included

 - Source home page.
 - Unified folder/file card grid.
 - Breadcrumb navigation.
 - URL-persisted folder selection.
 - Manual refresh.
 - System light/dark theme and responsive styling.
 - Accessible loading, empty, and error states.

 ### Excluded

 - Search, filters, and layout switching.
 - Document opening, preview, editing, or file operations.
 - Content snippets, thumbnails, timestamps, or file sizes.
 - Live agent directory integration.
 - Comparison, synchronization, authentication, or persistent history.
 - Permanent sidebar or split-pane workspace.

 Filesystem boundaries

 - Default to fixtures/pi/ and fixtures/claude/, resolved independently of the shell’s working directory.
 - Support MD_MANAGER_FIXTURE_ROOT for local experiments. The supplied root contains pi/ and claude/ subdirectories.
 - No request parameter may change the root or select a filesystem path.
 - Include regular .md files case-insensitively and directories, including empty directories.
 - Exclude symlinks and non-Markdown files.
 - Do not follow symlinked source directories or descendants.
 - Missing or unreadable sources produce an error, not a partial successful listing.
 - Remain single-user and localhost-only.

 API contract

 Replace GET /api/files with:

 ### GET /api/entries

 ```json
   {
     "entries": [
       { "source": "Pi", "path": "skills", "kind": "directory" },
       { "source": "Pi", "path": "skills/review.md", "kind": "file" },
       { "source": "Claude", "path": "workflow.md", "kind": "file" }
     ]
   }
 ```

 - source is "Pi" or "Claude".
 - path is source-relative and uses / separators.
 - kind is "directory" or "file".
 - Return all eligible descendants as one flat list.
 - Source roots are implicit, not entries.
 - Return deterministic ordering.
 - Accept no path or root selector.
 - On discovery failure, return HTTP 500 with a useful message that does not expose absolute filesystem paths.
 - The client constructs the folder tree from this response.
 - Refresh requires one refetch, not requests per directory.

 Design

 ```text
   MD Manager

   Home / Pi / skills                         ↻ Refresh

   ┌──────────────────┐  ┌──────────────────┐
   │ Folder icon      │  │ Folder icon      │
   │ deployment       │  │ review           │
   │ Folder           │  │ Folder           │
   └──────────────────┘  └──────────────────┘
   ┌──────────────────┐  ┌──────────────────┐
   │ MD               │  │ MD               │
   │ code-review.md   │  │ implementation.md│
   │ Markdown         │  │ Markdown         │
   └──────────────────┘  └──────────────────┘

   2 folders · 2 files
 ```

 ### Home

 - Display Pi and Claude source cards.
 - Each card contains a source label, icon, and short description.
 - Selecting a source opens its root directory.

 ### Folder view

 - Display immediate children only.
 - Use one grid with the same card structure for directories and files.
 - Sort folders first, then Markdown files; alphabetical within each group.
 - Each card contains an icon, complete name, and type label.
 - Folder cards are navigation links.
 - File cards are non-interactive and must not imply that clicking opens them.
 - Show immediate folder and file counts below the grid.

 ### Navigation

 - Breadcrumbs begin with Home, followed by source and directory segments.
 - Store the current folder in the URL, encoding each path segment.
 - Support direct links, reloads, and browser back/forward navigation.
 - Names containing spaces, #, ?, or % must work.
 - Entering a folder starts at the top.
 - Returning through browser history restores the prior listing position.
 - Missing folders show an explanation and a link to the source root.

 ### Refresh

 - Provide a labeled Refresh button.
 - Disable repeated refresh requests while pending.
 - Update cards and counts together.
 - Preserve the current folder when it still exists.
 - On refresh failure, retain the previous listing and label it as potentially outdated.

 Visual and responsive requirements

 - Minimal developer-tool styling with system light/dark preference.
 - Consistent card widths, padding, icon positions, and type labels.
 - Subtle borders and restrained hover styling on interactive cards only.
 - Allow long names to wrap without clipping.
 - Equal-height cards within each grid row.
 - Responsive columns, reaching one column when necessary.
 - No horizontal page scrolling.
 - Collapse intermediate breadcrumbs through an accessible expansion control on narrow screens.
 - Use one page-level scroll area.

 Accessibility

 - Semantic list structure for the grid.
 - Real links for source cards, folder cards, and breadcrumbs.
 - One keyboard focus target per navigable card.
 - Visible focus indicators.
 - DOM order matches visual order.
 - Mark the current breadcrumb with aria-current.
 - Announce loading and refresh outcomes without unexpected focus movement.
 - Meet WCAG AA color contrast.

 Acceptance criteria

 - Both sources are navigable through cards and breadcrumbs.
 - Empty directories appear and remain navigable.
 - Only eligible Markdown files appear as file cards.
 - Folders precede files with alphabetical ordering within each group.
 - Duplicate filenames remain distinguishable by source and path.
 - Encoded folder URLs survive reloads and browser history.
 - Refresh reflects additions and removals on disk.
 - Counts represent immediate children.
 - Long names remain readable on narrow screens.
 - A scratch fixture tree containing several hundred files renders without visible delay.
 - Navigation and refresh work entirely by keyboard.
 - No file contents are fetched or displayed.

 Testing and delivery

 - API tests use createApp with temporary roots.
 - Cover nested and empty directories, uppercase .MD, ignored extensions, symlink exclusion, and source failures.
 - Browser tests use the default fixture root and one Playwright worker.
 - Mutation-based test setup creates uniquely named artifacts and removes them in afterEach, including on failure.
 - Never modify committed sample files.
 - End the suite by asserting no modified or untracked files under fixtures/.
 - Cover ordering, navigation, encoded URLs, refresh, responsive layouts, and all states.
 - Lint, tests, and production build must pass.
 - Update README with the endpoint, environment variable, read-only scope, and fixture testing rules.
