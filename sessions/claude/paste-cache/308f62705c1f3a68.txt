PRD: Free-Form Graph Explorer

 Status

 Agreed scope, ready for implementation planning.

 Goal

 Replace the existing Markdown file table with an interactive, free-form 2D graph. Users explore Pi and Claude fixture directories by expanding folder nodes and following containment connections.

 The graph should reveal directory structure without imposing a horizontal or vertical hierarchy.

 Project context

 - React, Vite, and TypeScript frontend.
 - Fastify and TypeScript backend.
 - The existing GET /api/files endpoint lists fixture Markdown filenames.
 - Sources are fixtures/pi/ and fixtures/claude/.
 - This implementation is read-only: discover names and directories without reading document contents.

 Scope

 ### Included

 - Free-form 2D directory graph.
 - Source, directory, and Markdown-file nodes.
 - Containment edges.
 - Progressive directory expansion and collapse.
 - Node dragging and session-level pinning.
 - Pan, zoom, fit-to-view, and reset controls.
 - Breadcrumb navigation.
 - URL-persisted folder selection.
 - Manual refresh.
 - System light/dark theme and responsive styling.
 - Keyboard navigation and an accessible outline fallback.
 - Loading, empty, and error states.

 ### Excluded

 - Reference, hyperlink, or dependency extraction.
 - Connections inferred from matching filenames.
 - Search and filters.
 - Document opening, preview, editing, or file operations.
 - Content snippets, thumbnails, timestamps, or file sizes.
 - Live agent directory integration.
 - Comparison, synchronization, authentication, or persistent history.
 - Permanent sidebar or split-pane workspace.
 - Persistent storage of graph positions.

 Filesystem boundaries

 - Default to fixtures/pi/ and fixtures/claude/, resolved independently of the shell’s working directory.
 - Support MD_MANAGER_FIXTURE_ROOT for local experiments. The supplied root contains pi/ and claude/ subdirectories.
 - No request parameter may change the root or select a filesystem path.
 - Include regular .md files case-insensitively and directories, including empty directories.
 - Exclude symlinks and non-Markdown files.
 - Do not follow symlinked source directories or descendants.
 - Missing or unreadable sources produce an error, not a partial successful listing.
 - Remain single-user and localhost-only.

 API contract

 Replace GET /api/files with:

 ### GET /api/entries

 ```json
   {
     "entries": [
       { "source": "Pi", "path": "skills", "kind": "directory" },
       { "source": "Pi", "path": "skills/review.md", "kind": "file" },
       { "source": "Claude", "path": "workflow.md", "kind": "file" }
     ]
   }
 ```

 - source is "Pi" or "Claude".
 - path is source-relative and uses / separators.
 - kind is "directory" or "file".
 - Return all eligible descendants as one flat list.
 - Source roots are implicit, not entries.
 - Return deterministic ordering.
 - Accept no path or root selector.
 - On discovery failure, return HTTP 500 with a useful message that does not expose absolute filesystem paths.
 - The client constructs the directory graph from this response.
 - Expansion requires no additional API calls.
 - Refresh requires one refetch.

 Graph model

 ### Nodes

 Three node types:

 ┌───────────────┬─────────────────────────────────────┬─────────────────────────────────────────┐
 │ Type          │ Appearance                          │ Behavior                                │
 ├───────────────┼─────────────────────────────────────┼─────────────────────────────────────────┤
 │ Source        │ Large, distinctly labeled node      │ Select, expand, collapse, drag, and pin │
 ├───────────────┼─────────────────────────────────────┼─────────────────────────────────────────┤
 │ Directory     │ Folder-shaped or folder-marked node │ Select, expand, collapse, drag, and pin │
 ├───────────────┼─────────────────────────────────────┼─────────────────────────────────────────┤
 │ Markdown file │ Smaller document-marked node        │ Displays filename; no document action   │
 └───────────────┴─────────────────────────────────────┴─────────────────────────────────────────┘

 - Identify entries by source plus relative path.
 - Distinguish types through shape, icon, and text—not color alone.
 - File nodes may be repositioned through graph controls but do not open or select documents.

 ### Edges

 - Every edge means contains.
 - Connect each directory or file to its immediate parent.
 - Connect top-level entries to their source node.
 - Use a subtle directional indicator to distinguish parent from child.
 - Do not connect Pi and Claude artificially.
 - Do not draw references or dependencies.
 - Include a legend explaining node types and containment edges.

 Design direction

 - Use a force-directed layout in free 2D space.
 - Connected nodes attract; unrelated nodes repel.
 - Do not assign fixed rows, columns, depth bands, or horizontal/vertical tree alignment.
 - Pi and Claude form independently recognizable clusters.
 - Let the simulation settle rather than moving continuously.
 - Preserve spatial orientation when expanding, collapsing, or refreshing.
 - Avoid automatically fitting the entire graph after every interaction.

 ### Page structure

 - Header with application title and Refresh.
 - Breadcrumb bar above the graph.
 - Graph toolbar with zoom, fit, reset, and outline controls.
 - Graph canvas occupies the remaining workspace.
 - Small node/edge legend.
 - No permanent detail pane.

 Functional requirements

 ### Initial view

 - Show only the Pi and Claude source nodes.
 - Fit both source nodes into the initial viewport.
 - Do not expand the entire tree automatically.

 ### Expansion and collapse

 - Source and directory nodes have explicit expansion controls.
 - Expanding reveals immediate children only.
 - An expanded child directory retains its own expansion state while visible.
 - Collapsing hides all descendants of that node and clears their expansion state.
 - Empty directories remain visible and show that they contain no eligible entries.
 - Arrange newly revealed children near their parent without resetting unrelated node positions.
 - If collapsing would hide the selected folder, select the collapsing parent and update the URL.

 ### Folder selection

 - Selecting a source or directory updates the breadcrumb and URL.
 - Selection and expansion are separate actions.
 - Highlight the selected folder and its visible containment connections.
 - Display its immediate folder and Markdown-file counts near the breadcrumb.
 - Markdown-file nodes have no document-selection action.

 ### Navigation and URLs

 - Breadcrumbs begin with Home, followed by source and directory segments.
 - Store the selected folder in the URL, encoding every path segment.
 - Support direct links, reloads, and browser back/forward navigation.
 - Names containing spaces, #, ?, or % must work.
 - Opening a folder URL reveals its ancestor chain, expands the selected folder, and brings it into view.
 - Breadcrumb navigation selects and reveals the destination without resetting unrelated branches.
 - Home clears folder selection and fits the currently visible graph.
 - Missing folders show an explanation and navigation to the source root.
 - Node coordinates and viewport position are not encoded in the URL.

 ### Dragging and pinning

 - Users can drag nodes to arrange the workspace.
 - A dragged node becomes pinned at its new position.
 - Provide an accessible way to unpin a node.
 - Pinned positions survive selection changes and refresh within the current session when the node still exists.
 - Reloading may generate a new arrangement.

 ### Canvas controls

 - Support pointer/touch panning and zooming.
 - Provide visible Zoom in, Zoom out, and Fit controls.
 - Fit frames all currently visible nodes.
 - Reset clears pins and expansion state, returns to Home, and shows the two source nodes.
 - Dragging must not accidentally trigger selection or expansion.
 - Bound zoom to usable minimum and maximum levels.

 ### Refresh

 - Refetch the full entries list.
 - Disable repeated refresh requests while pending.
 - Preserve existing selection, expansion, and node positions where possible.
 - Add new nodes only when their parent is expanded.
 - Remove entries that no longer exist.
 - If the selected folder disappears, show the missing-folder state.
 - On failure, retain the previous graph and label it as potentially outdated.

 Visual and responsive requirements

 - Minimal developer-tool styling with system light/dark preference.
 - Clear labels, restrained edge styling, and visible selection states.
 - Use collision avoidance to reduce node overlap.
 - At normal viewing scale, filenames remain readable and can wrap.
 - At distant zoom levels, labels may be abbreviated or hidden; full names remain available accessibly.
 - Respect reduced-motion preferences by avoiding animated layout transitions.
 - Use a bounded graph viewport rather than creating horizontal page scrolling.
 - Keep controls reachable on narrow screens.
 - Collapse intermediate breadcrumbs through an accessible expansion control.
 - Do not rely on hover for essential information or controls.

 Accessibility

 - Provide an outline mode using the same data and expansion state, replacing—not accompanying—the graph.
 - The outline supports folder navigation, expansion, breadcrumbs, and refresh.
 - Provide keyboard access to visible graph nodes and all toolbar controls.
 - Use a documented, predictable keyboard order independent of node coordinates.
 - Provide keyboard-operable selection, expansion, collapse, pinning, and unpinning.
 - Pointer dragging must not be required to browse.
 - File nodes expose names and types without implying document-opening behavior.
 - Mark the current breadcrumb with aria-current.
 - Announce loading, refresh outcomes, and expansion changes appropriately.
 - Meet WCAG AA color contrast.

 │ State                  │ Behavior                                                                      │
 ├────────────────────────┼───────────────────────────────────────────────────────────────────────────────┤
 │ Initial loading        │ Loading message or graph placeholder.                                         │
 ├────────────────────────┼───────────────────────────────────────────────────────────────────────────────┤

 ├────────────────────────┼───────────────────────────────────────────────────────────────────────────────┤

 │ Missing folder         │ Explanation and source-root navigation.                                       │
 ├────────────────────────┼───────────────────────────────────────────────────────────────────────────────┤

 Acceptance criteria

 - Both fixture sources appear as distinct graph roots.
 - Layout is free-form 2D, not a fixed horizontal or vertical tree.
 - Every edge corresponds to an actual parent-child relationship.
 - Expansion reveals immediate children without fetching additional data.
 - Collapse removes descendants from view.
 - Empty directories remain visible and navigable.
 - Non-Markdown files and symlinks do not appear.
 - Duplicate filenames remain distinguishable by source and path.
 - Direct links reveal the selected folder and its ancestor chain.
 - Encoded folder URLs survive reloads and browser history.
 - Dragged nodes remain pinned until unpinned or reset.
 - Expansion and refresh do not reset the entire layout.
 - Refresh reflects additions and removals on disk.
 - Pan, zoom, fit, collapse, and reset work on desktop and narrow screens.
 - A scratch fixture tree containing several hundred files loads without visible delay; progressive expansion remains responsive.
 - Keyboard and outline navigation provide access to every directory.
 - No file contents are fetched, displayed, or parsed.
 - No reference or dependency edges are invented.

 Testing and delivery

 - API tests use createApp with temporary roots.
 - Cover nested and empty directories, uppercase .MD, ignored extensions, symlink exclusion, and source failures.
 - Browser tests use the default fixture root and one Playwright worker.
 - Mutation-based test setup creates uniquely named artifacts and removes them in afterEach, including on failure.
 - Never modify committed sample files.
 - End the suite by asserting no modified or untracked files under fixtures/.
 - Cover graph construction, expansion/collapse, URL navigation, refresh, pin/reset behavior, outline access, and all states.
 - Assert graph relationships and user-visible behavior rather than exact simulation coordinates.
 - Ensure layout animation does not make browser tests timing-dependent.
 - Lint, tests, and production build must pass.
 - Update README with the endpoint, environment variable, read-only scope, graph controls, accessibility controls, and fixture testing rules.
