Controller: the reviewer becomes a native session

workflow/interactive.py (the biggest structural change). The native launcher used to know only the two workers. It now has a SESSION_NODES tuple with review as a third node, a worktree_of helper (workers use their plan worktree, the reviewer uses review-worktree/), and the old monolithic run method was split into reconcile (bind an existing launch intent to its surviving session, never relaunch) and launch (journal intent, run claude --bg once, settle on the row it created). Workers still go through run. A new run_reviewer builds the reviewer command: --tools Read,Glob,Grep,Write, --allowedTools "Edit(//<run>/review.completion.json)", --permission-mode dontAsk, --add-dir <run>, --safe-mode, no MCP. The docstring records why the rule is spelled Edit, which the smoke test found. Pane handling was refactored into send_attach, and attach_reviewer_pane splits a third pane off the adapter pane in the run's existing tab; attach_panels creates three panes when a reviewer receipt exists, and attach-one --node review is accepted.

workflow/automatic.py. DEFAULTS gains reviewer_transport: native; validate_automatic tolerates plans without the key and reviewer_transport() maps those to print, so the first live run still validates. The old inline REVIEW_SCHEMA is replaced by completion_schema() (loaded from the committed JSON schema) and structured_review_schema() for print mode. review_candidate now only does the shared work (bundle validation, worktree, diff, receipt) and dispatches to review_native or review_print; both end in finish_review, which re-checks the worktree and evidence hashes, writes review.json for either verdict, and raises on a blocked verdict. wait_review polls the inventory, treats blocked as a waiting state with one timeline note, accepts the file when the session is idle, done or blocked, and hands it to read_review_completion, which validates schema and bindings. review_resumable lets drive re-enter a review node that an interrupt left running.

workflow/pipeline.py. stop_workers was generalised into stop_session(node), and stop markers now record stopped_at. validate_finding accepts findings with or without worker/requirement. prepare takes --feature and --reviewer-transport; preflight requires the --allowedTools flag. New validate_review_record and export_run, plus the export CLI action, which uses a lightweight runtime so a copied run directory exports.

workflow/launch.py. Feature choices are now project-workflows, review-result, run-inputs; run id and run root default from the feature; --reviewer-transport passes through; the prepare command carries --feature.

Contracts and export

contracts/workflow/v1.ts adds reviewFindingSchema and reviewCompletionSchema with validateReviewCompletion; the generated reviewCompletion.schema.json is new; examples and tests cover bindings and the approved-with-open-P1 rejection.

contracts/projects/v1.ts adds reviewResult (contract 1.1.0), runInputs, runInputsResponse and workerInputs (1.2.0), the optional requirement_verbatim flag on findings, and validators for each. Three generated schema files are new. The example run detail's review node now shows a session and result URI. The README documents the two routes, the per-message version rule and the projection rules for the review node and inputs.

workflow/export_state.py bumps the export to 1.2.0 and adds export_review (from review.json, the review receipt, the launch receipt and review.diff) and export_inputs (from plan, policy, receipts, completion, handoff and stop files, with task text truncated at 256 KiB). Both sections are null when their files are absent.

Tests, features and docs

Tests. test_automatic.py gained a FakeReviewerSessions fake, a shared prepare_graph fixture, a NativeReviewTests class (acceptance, rejected file, blocked verdict, deadline, interrupt-and-resume, four-process recovery) and WaitReviewTests; the old graph tests are pinned to print mode. test_interactive.py covers the reviewer launch flags, reconcile, the third pane and idempotency. test_export.py is new. test_feature_launch.py covers the new features and transport flag. test_pipeline.py asserts stopped_at.

Features. features/review-result/ and features/run-inputs/ are new: manifest, policy (ten and fourteen browser scenarios, no failure drill), README describing the export seam, and UI and adapter task files.

Docs. The runbook gains an "Automatic review session" section and export notes; the interactive-sessions note and the project-workflows README describe the third pane and new files; the four PRDs record decisions and status; docs/HANDOFF_REVIEW_VISIBILITY.md is the full record including both smoke attempts.
