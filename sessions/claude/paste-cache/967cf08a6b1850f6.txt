The shape of it

Before: the review node shelled out to one claude --print process, parsed its structured output, and that was the verdict. After: the review node launches a native background session that the operator can watch and type into, and the verdict arrives as a file bound to the exact run, bundle and candidate. The print path survives as an explicit opt-out.

Contract — contracts/workflow/

v1.ts (+29): new reviewCompletionSchema — envelope (contract_version, run_id), node_id literal 'review', launch_token, bundle_sha256, candidate_commit, verdict (approved/blocked), and findings of {severity, message, disposition, worker, requirement}. worker is ui | adapter | both | none; requirement is a non-empty string or null — a verbatim quote, never a paraphrase. Added to the schemas map (so it exports and is drift-tested), plus validateReviewCompletion, which enforces the two rules the schema can't: a blocked verdict must name findings, and an approval can't leave a P0/P1 unresolved.

reviewCompletion.schema.json (new, 104 lines): generated by npm run contracts:export. This is the file the Python controller validates against, so TS and Python share one definition.

examples.ts (+11): a reviewCompletion fixture with one open P2 carrying a requirement quote and one resolved P1 with requirement: null.

contract.test.ts (+29): three new tests — bindings (bad version, wrong node_id, empty token, short hash, non-SHA candidate, unknown verdict, extra field), findings (missing worker, unknown worker, empty quote, and worker: 'none' accepted), and verdict-vs-findings contradictions.

README.md (+3): the message table row, plus a paragraph saying schema validity proves nothing about authority — the controller must also check the bindings, that the reviewer isn't either worker, and that evidence didn't change mid-review.

Controller — workflow/

sessions.py (+6): REVIEWER = "reviewer" and file_prefix(), which maps the reviewer's node id to the review filename stem. That's why the runtime files are review.interactive.json, review.completion.json, review.stop.json, review.launch.log — matching the graph node name, not the session name.

interactive.py (+138/−~20):
- worktree() and receipt_path() on InteractiveSessions; locate() now goes through them instead of indexing plan["nodes"]. This is the load-bearing refactor: the reviewer inherits the workers' whole identity chain (exact background id from the launch log, kind == background, cwd match, name match, UUID stability, live PID, os.kill(pid, 0)) with no duplicated logic.
- run_reviewer(prompt, launch_token, commit): reconciles an existing receipt or launches claude --bg --name workflow-<run>-reviewer in review-worktree/, refusing if the worktree isn't the clean reviewed candidate or a session already holds that name. reviewer_tools = "Read,Glob,Grep,Write" and reviewer_permission_mode = "dontAsk" are class constants — deliberately one-line changeable if the live test shows dontAsk blocks the write. Strips HERDR_* from the environment, reuses settle() for the late-registering PID, and on any failure writes needs_reconciliation rather than retrying.
- attach_pane() extracted from attach_panels' final loop (no behaviour change for workers), and attach_reviewer_pane() added: requires terminals.json with both workers in one tab, verifies the reviewer session, splits the adapter pane downward, records the mapping before typing anything, then runs attach-one. Returns early if a reviewer pane already exists.
- CLI: --node now accepts reviewer; attach-one resolves the receipt and cwd through the new helpers.

automatic.py (+238/−~55):
- DEFAULTS gains reviewer_transport: "native"; TRANSPORTS, REQUIRED_SETTINGS and transport(plan) added. validate_automatic changed from set(settings) != set(DEFAULTS) to REQUIRED ⊆ settings ⊆ DEFAULTS — that's what keeps project-workflows-001's existing plan valid (I verified it loads and reports native).
- REVIEW_FINDING/REVIEW_SCHEMA: findings now require worker and requirement in both transports, so the two produce the same shape.
- review_instructions() (shared prompt) and review_completion_prompt() (native only: the file path, the schema path, the exact values to copy back, and "ending your turn without this file is not a verdict").
- read_review_completion(): symlink/size guard, JSON-Schema validation, the four bindings, then the two cross-field rules mirrored from v1.ts.
- wait_review(): mirrors wait_handoffs — deadline from the receipt's launch_requested_at, missing session → reconcile, blocked state → stop, and the file only counts when the session is idle or done.
- review_worktree(): extracted; creates the worktree and diff, or on resume re-verifies HEAD, cleanliness and the patch hash instead of overwriting.
- review_candidate() split into native_review() and print_review(). Idempotence changed: succeeded short-circuits as before, blocked or a hash mismatch still refuses, but a native launching/running receipt now resumes. KeyboardInterrupt is re-raised without marking the receipt blocked — that's what leaves the reviewer alive.
- resumable_review() and a failures == ["review"] branch in advance_failed_checks, gated on a native transport, a running receipt and a locatable session.
- drive() catches KeyboardInterrupt around graph.invoke to log the resume note; RESUME_NOTE reworded to cover the reviewer.

pipeline.py (+102/−~35):
- stop_workers split into stop_session(node) (the per-session body, unchanged logic, now prefix-aware) plus the workers' cross-check, and stop_reviewer() added with its own restart check and a review/stopped event mentioning the resumable transcript.
- launch_reviewer(): event, run_reviewer, an event naming the session UUID and worktree, then a best-effort attach_reviewer_pane whose failure logs review/detached instead of killing the run.
- validate_review findings check loosened from exact-key equality to a subset/superset range, with worker and requirement validated when present — so old reviews still pass.
- prepare gains --reviewer-transport; passing it without --automatic errors.

launch.py (+16): --reviewer-transport threaded through launch_commands and pinned into the generated prepare command, validated before any command runs.
