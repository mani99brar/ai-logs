Routine contract:



Trigger: manual invocation before preparing a deployment.

Inputs: source chain Id, target chain ID, required bridges

Input version: a deterministic hash of relevant input contents and configuration, excluding secrets.

Permissions: read approved records, officail contract directories and read-only RPC data; write only designated output and evidence files.

Owner: repository operator.

Output: deployment-ready mathcing hte env.example plus a verification report with source references and input version.

Failure: visible diagnostics and a nonzero exit code; preserve any previous valid configuration.

Independent verification:



Required contracts are present and addresses have valid syntax.

Each address matches its referenced trusted record for the target chain.

Conflicting or missing records fail explicitly.

RPC chain ID matches the requested chain.

Expected deployed contracts have nonempty bytecode.

Where authoritative identity checks exist in the repository, use them. Bytecode presence alone does not prove contract identity; report the verification level and any limitations.

Record verification evidence without exposing RPC credentials.
