    workflow: give browser lanes a check-report command that runs where they are
    
    The pinned sentence, the init template, the RUNBOOK and the PRD told lanes to
    run a bare `python -m workflow check-report features/<feature> ...`, which a
    lane cannot run: `python` is not on this machine's PATH, a target's worktree
    cannot import `workflow`, the feature-directory form imported LangGraph through
    launch and pipeline, and `"$PY" -m workflow` needed the tool's checkout and
    the target's worktree as the working directory at once. A lane told to check
    its report would have hit these errors, and a misnamed screenshot:<id> would
    again have surfaced only at the candidate.
    
    - The pinned task of a browser lane now ends with the exact command:
      PYTHONSAFEPATH=1 PYTHONPATH=<tool> <controller interpreter> -m workflow
      check-report "$(git rev-parse --show-toplevel)/../policy.json" <lane>
      <tmp>/report.json. The policy is the run's pinned policy.json beside the
      lane's worktree (<run>/worktree-<lane>), the one the verifier applies, so
      the command needs no feature name and works from anywhere in the worktree.
      PYTHONSAFEPATH keeps a target's own `workflow` package from shadowing the
      tool's. Only module-level values are used: pinned_task and repin keep their
      signatures.
    - report_policy reads feature.json's `policy` key itself, with
      launch.feature_file's escape check, so check-report needs jsonschema but
      not LangGraph.
    - The init template keeps the rules and the Playwright report command and
      points at the appended check-report command instead of naming an
      interpreter; the RUNBOOK, README and PRD section 6 show the spelled-out
      form and why.
    
    Tests: the pinned command, extracted from pinned_task, runs through bash from
    the root and a subdirectory of a lane worktree outside the tool that holds a
    shadowing `workflow` package; check-report on a feature directory runs from
    outside the tool with every langgraph import failing.
