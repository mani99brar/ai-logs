    workflow: repair a frozen lane with an operator's fix commit, before review
    
    workflow-guardrails-001 ended blocked at the combined candidate: the ui lane's
    browser evidence failed twice identically, frozen snapshots cannot change, and
    the only way on was a new run. The hand finish committed the fix on the pinned
    source branch, which moves HEAD off the base that integration requires and puts
    the fix outside every gate.
    
    `python -m workflow repair "$RUN" <lane>[,<lane>] --commit <sha> --reason ...`
    (lane-repair-design.md, version 1) turns a fix commit made on the failing
    candidate or on the lane's snapshot into a new snapshot per named lane: the
    snapshot plus the fix's files the lane owns, checked with freeze's ownership
    rules (now Pipeline.check_ownership), committed with the base as parent and the
    recorded time as date so a rerun makes the same commit. It journals every step
    in repairs.json (S1-S6, each idempotent: a crash is completed by rerunning the
    identical command, and drive() and retry refuse meanwhile), raises the attempt
    counters past the existing evidence with per-revision floors, and forks the
    checkpoint at the freeze boundary with fork.config. Updating the failed head
    instead would schedule the candidate beside the verifies with the new snapshots
    and the old packets. It launches nothing, runs no check and never invokes the
    graph: automatic --live (or retry for a manual run) re-verifies the repaired
    lane, rechecks the others, checks a new candidate generation (candidate-<g>)
    for every lane and only then reaches review, whose prompt names the repair.
    `--workspace` makes a detached worktree at the right base with a brief of the
    blocking reasons, so nobody commits on the source branch again.
    
    Around it: the attempt limit counts per lane, phase and revision; the
    identical-failure guard compares only attempts of the same revision and now
    leaves a `controller blocked` event instead of ending the timeline at
    "controller running"; candidate() refuses worker packets of another revision
    and a candidate that differs from a repaired candidate's tree.
