resume: the override needs an attempt that read the pinned files; a failed rerun re-exports

Review of slice 2 (findings 4, 5, 16, 17, 18) found these gaps in resume.

A rerun re-pins the edited feature files (and moves the base) before its
challenge job runs. When that job failed, challenge.json kept the previous
attempt's paused record and its pinned digests, and --accept-challenge
accepted it: the workers then launched on feature text no challenge had
read, and the accepted record the viewer shows described other inputs.
The override now compares the paused record's pinned digests with the
plan's copies and refuses on a mismatch, naming what differs, and tells
the operator to rerun resume without --accept-challenge. Refusing keeps
the operator's edits. Deferring the plan.json write instead would have let
a later override launch the old text and silently drop them. A failed
rerun whose inputs match the paused attempt is still accepted, because
that attempt read what the workers get.

A paused resume already re-exported run-state.json (challenge-resume). A
failed one did not: plan.json named the moved base while the export kept
the old one, which the Projects server refuses as a disagreement about the
run identity, and the export lacked the blocked event. resume now
re-exports whenever resume_challenge raises, the same report `status`
writes under the run lock.

A detached HEAD in the source checkout made commit_revision raise git's
raw CalledProcessError. It is now the same refusal as another branch,
saying the HEAD is detached.

Tests that could not fail now can. ChallengePauses recorded nothing about
the resumed launch, so removing the runtime rebuild still passed.
RecordingSessions now keeps each launch's plan digest and worker prompt,
and the test asserts that they are the re-pinned plan's. The attempt-3
resume also edits decisions.md and the PRD, so removing either re-pin
fails the test. The attempt-2 pause raises a new concern, and the export
must show it. A new class drives an automatic run through a paused resume
(no supervisor) and an override (supervise called once with the run
directory, after both launches). Each of these mutations was checked to
fail a test.

The RUNBOOK, the README and PRD 4.5 describe the new refusal and the
re-export. The PRD's slice 2 bullet no longer calls the challenge a new
graph node.
