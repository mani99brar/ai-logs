Exit 69 when Claude Code is unavailable in any graph node; resume an interrupted freeze

drive raised a TransientInfraError from graph.invoke only when the review
wait had recorded its interruption. From any other node it was swallowed as
an ordinary node failure, so automatic-step exited 75 ("checkpoint
persisted") and the supervisor started a step that then classified it as a
verdict. The freeze was the worst case: it runs inside the resumed handoff
node, and when its worker stop lost the `claude agents` listing (or the
`claude stop` exec) for 60 seconds, LangGraph left no next step while the
handoff task kept its error and its worker_handoff interrupt. Every later
drive stopped at "No verified feature-branch completion" and `retry`
refused, although the RUNBOOK promises that `automatic --live` resumes after
exit 75 and the stop intents were already on disk.

A TransientInfraError from any node is now raised from drive after an
`interrupted` event, so the step exits 69 and `automatic` exits 75. When
the freeze was interrupted, freeze-interrupted.json records the cause. The
next drive sees the failed handoff, removes the marker and re-enters the
freeze once through the same worker_handoff branch: wait_handoffs checks
the recorded handoffs against the stop intents, stop_session confirms the
stops already issued (or follows a respawned PID) and stops the rest, and
nothing is relaunched. A freeze that failed without the marker (a stop that
failed, ownership, a moved HEAD) is not re-entered, so the supervisor cannot
loop on it, and it is reported as "Freeze failed: <error>" instead of "No
verified feature-branch completion". A reviewer launch an outage interrupts
still leaves the review at needs_reconciliation, as documented; only its
exit code changes.

The RUNBOOK no longer lists a missing session as a verdict: it describes
the respawn gap the waits and stops wait out, the freeze's re-entry and its
marker, and what to check when a session stays missing.

Wait out an update's respawn gap in the controller's waits and stops

A Claude Code update restarts the background service, which about 15
seconds later (and at any later time) respawns idle sessions onto the new
binary under new PIDs: finished lanes, lanes paused on a question, reviewers
that wrote their files. Between the two processes `claude agents --json`
omits the session, lists its ended PID, a row without a PID or a state
between two processes. attach-one waits this out (3e85a14, 9861d0e); the
controller did not. wait_handoffs raised "Native worker missing" (or
locate's "Native process is unavailable", "No live native PID", "Session is
not attachable"), plain RuntimeErrors, so drive recorded `controller
blocked` and stopped every worker, and wait_reviews blocked the review the
same way: an update from another Claude session on the machine could end a
run after hours of worker time. The freeze's stop refused the same gaps,
and a stop retried after a respawn failed forever with "identity changed
after stop intent", since the intent pinned the old PID.

attach-one's classification of one listing moves into verified_row, which
observe and a new UpdateGaps share. For a node whose receipt is bound, a
missing row, a dead or zombie PID, a row without a PID and a non-terminal
state locate refuses are a gap: wait_handoffs and wait_reviews skip that
node at this poll and look again at the next, for DEAD_PID_GRACE_SECONDS
(the constant attach-one uses) from when the gap was first seen; a longer
gap is TransientInfraError, so the run stops nothing and exits 75.
stopped/failed rows and identity, cwd or name mismatches stay immediate
verdicts, and a receipt not bound yet keeps locate's plain answer.
stop_session looks its session up the same way (re-listing every 2
seconds), and a row with the intent's background id and session UUID under
a new live PID is a respawn: the intent takes the new PID and that process
is stopped. A UUID listed under another background id is still a changed
identity.

The WorkerQuestion fake now lists a live PID in its rows, as a real
locate always does.
