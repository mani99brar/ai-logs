# Design spec: Review visibility and run inputs (slices A, B, C)

This spec pins every cross-boundary shape so three workstreams (P = Python controller, S = server adapter, U = UI + browser tests) can be built in parallel and integrate without renegotiation. The PRDs are `docs/PRD_REVIEW_VISIBILITY.md`, `docs/PRD_REVIEWER_PANE.md`, `docs/PRD_REVIEW_RESULT.md`, `docs/PRD_RUN_INPUTS.md` in the repository. The projects contract is ALREADY WRITTEN and is the source of truth for the HTTP payloads: `contracts/projects/v1.ts` (`reviewResultSchema`, `runInputsSchema`, `validateReviewResult`, `validateRunInputs`), `contracts/projects/examples.ts`, `contracts/projects/README.md`, and `contracts/workflow/reviewCompletion.schema.json` (the reviewer completion file). Read those four files first. Do not change them (if you believe one is wrong, report it in your final output instead).

## 1. Vocabulary

- Workers: logical `ui` / `adapter` (graph launch nodes `launch_ui` / `launch_adapter`; verification nodes `verify_ui` / `verify_adapter`).
- Reviewer: graph node `review`. Native session name `workflow-<run_id>-reviewer`, pane label `Claude: reviewer`, receipts `review.interactive.json`, `review.completion.json`, `review.stop.json`, `review.launch.log`, worktree `<run>/review-worktree`.
- Run directory files (existing): `plan.json`, `policy.json`, `events.jsonl`, `run-state.json` (export), `<worker>.interactive.json` (launch receipt), `<worker>.completion.json` (worker's completion signal, automatic mode), `<worker>.handoff.json` (accepted handoff), `<worker>.stop.json`, `review-bundle.json`, `review.diff`, `review.json` (accepted review), `automatic-review.json` (review protocol receipt), `verification/<phase>/<node>/<attempt>/packet.json`.

## 2. Export format: `run-state.json` version 1.2.0 (produced by `workflow/export_state.py`, consumed by `server/projects.ts`, mimicked by `tests/project-workflows/seed.ts`)

Everything from 1.0.0 stays exactly as is (`version`, `run_id`, `base_commit`, `created_at`, `updated_at`, `definition`, `values`, `next`, `tasks`, `events`, `verification_packets`). Two keys are added. `version` becomes `"1.2.0"`. The adapter must accept versions `1.0.0` (no `review`/`inputs` keys), `1.1.0` (`review` key, no `inputs`) and `1.2.0` (both). When a key is present its value is the object below or `null`.

```jsonc
"review": null | {
  "attempt": 1,
  "transport": "native" | "print" | "manual",
  "reviewer_session_id": "dd7bdcd1-adec-4efe-bcd4-bbadc3525d95",   // Claude session UUID, or the operator-stated identity for manual reviews (review.json "reviewer")
  "independent": true,
  "bundle_sha256": "<64 hex>",
  "candidate_commit": "<40 hex>",
  "verdict": "approved" | "blocked",
  "findings": [ { "severity": "P0|P1|P2", "message": "...", "disposition": "open|resolved|accepted",
                  "worker": "ui|adapter|both|none" | null, "requirement": "verbatim quote" | null } ],
  "reviewed_at": "2026-09-21T15:42:27.848828Z",                    // ISO 8601, UTC, trailing Z
  "diff": null | { "path": "review.diff", "sha256": "<64 hex>", "bytes": 289187 }   // relative to the run root
},
"inputs": null | {
  "feature": "Project-scoped workflow graph and run viewer",     // policy.json "feature"
  "policy_version": "1.1.0",
  "base_commit": "<40 hex>",
  "source_branch": "feature/project-workflows/project-workflows-001" | null,
  "mode": "automatic" | "manual",                                  // "automatic" iff plan.json has "automatic"
  "automatic": null | { "finish": "verified-feature-branch", "permission_mode": "bypassPermissions",
                        "worker_timeout_seconds": 3600, "review_timeout_seconds": 1800, "reviewer_transport": "native" | "print" },
                                                                  // reviewer_transport defaults to "native" when the plan predates it
  "setup": [ { "argv": ["npm", "ci"], "command": "npm ci", "timeout_seconds": 600 } ],   // command = Python shlex.join(argv)
  "max_verification_attempts": 3,
  "failure_drill": null | { "node_id": "adapter", "phase": "worker", "attempt": 1 },
  "workers": {
    "ui": {
      "role": "frontend",
      "task": "<plan.nodes.ui.task verbatim>",                     // authored task + "\nApproved ownership and checks:\n{...}"
      "prompt": "<contents of ui.prompt.txt>" | null,               // the exact prompt the native session received; null when the run did not record it
      "owned_paths": ["src/App.tsx", "..."],
      "checks": [ { "id": "frontend-build", "kind": "build", "argv": ["npm","run","build"], "command": "npm run build", "timeout_seconds": 180, "scenarios": [ {"id": "...", "description": "..."} ] } ],
      "launch": null | { "session_id": "<uuid>" | null, "launch_token": "<uuid>", "launch_requested_at": "2026-09-21T14:33:25.331982Z",
                         "native_started_at": 1790001207771 | null,   // epoch milliseconds as claude agents reports it
                         "observed_state": "working" | null, "status": "attached_session_available", "launcher_invocations": 1, "background_id": "68269267" | null },
      "completion": null | { "status": "completed" | "blocked", "summary": "...", "open_assumptions": ["..."] },
      "handoff": null | { "summary": "...", "open_assumptions": ["..."] },
      "stop": null | { "stopped": true, "confirmed_at": "2026-09-21T14:59:12.000000Z" | null }   // confirmed_at = stop.json mtime when stopped, else null

```

Derivation rules (Python side, all read-only, all files optional except plan.json):
- `review`: `null` unless `review.json` exists. `transport`: `native` if `review.interactive.json` exists; else `print` if `automatic-review.json` exists; else `manual`. `reviewer_session_id` = `review.json["reviewer"]`. `reviewed_at`: `automatic-review.json["accepted_at"]` when present, else the time of the last `events.jsonl` record with `node == "review"`, else the mtime of `review.json`. `diff`: sha256 + size of `review.diff` when it is a regular file, else null. `findings[].worker` / `requirement` = the values in review.json, `null` when the key is absent (reviews recorded before slice A).
- `inputs`: `null` when `policy.json` is missing (very old fixtures); otherwise built from `plan.json` + `policy.json` + receipts. `launch.launch_requested_at` is normalised to a trailing-`Z` timestamp (receipts store `+00:00`). Worker `role`, `owned_paths`, `checks` come from the policy worker entry. `completion` is the raw `<worker>.completion.json` reduced to `{status, summary, open_assumptions}` (no validation beyond shape; a malformed file → `null`).
- `export_state` keeps its "unchanged content does not bump updated_at" rule; a re-export whose content differs (new version/sections) bumps `updated_at`. Hashing `review.diff` on every export is acceptable.

Adapter-side rules (TS): `exportSchema.version` accepts `'1.0.0' | '1.1.0' | '1.2.0'`; `review`/`inputs` optional-or-null; a present section is validated strictly (`RUN_STORAGE_INVALID` on violation, naming the run but never a path). Payload projection:
- `reviewResult.reviewer.session_id` = `reviewer_session_id`; `reviewed_at` passed through; `findings[].message` and `requirement` through `redactPaths`; `requirement_found_in` computed against the RAW (pre-redaction) `inputs.workers.<lane>.task` and `prompt` texts: lane included iff `requirement` is a verbatim substring of that lane's task text (or, when the task is missing, its prompt); empty when `requirement` is null or `inputs` is absent. `diff` = `{ artifact_id: "patch-review-" + sha256.slice(0,12), kind: "patch", uri: <run route>/artifacts/<artifact_id>, sha256 }` or null.
- `runInputs`: `workers` as an array in policy order with `node_id` = lane (`ui`), `launch_node_id` = `launch_<lane>` if that node exists in the pinned definition, else the lane; `task`/`prompt` texts through `redactPaths`, truncated to 65536 characters with the marker `\n\n[… truncated by the viewer API: N more characters]` and `truncated: true`; `launch.native_started_at` epoch ms → ISO Z string; `launch.launch_requested_at` normalised to Z; `setup[].command`, `checks[].command` passed through (never re-joined); `stop.confirmed_at` passed through.

### 3.2 Native reviewer launch (`interactive.py`)
- `InteractiveSessions` learns the reviewer as node `"review"`: `launch_name("review") == f"workflow-{run_id}-reviewer"`; `node_worktree(node)` returns the plan worktree for workers and `self.directory / "review-worktree"` for `review`; `locate(node, rows)` uses `node_worktree` (keeping every existing identity check: plan digest, background kind, cwd, name, UUID format, live PID, attachable state). `settle` unchanged.
- New method `run_reviewer(self, prompt: str, launch_token: str, candidate_commit: str) -> dict`: mirrors `run()` for the reviewer. Precondition: `review-worktree` exists, `git rev-parse HEAD == candidate_commit`, clean status. Refuses a conflicting launch name. Writes `review.interactive.json` with the same keys as worker receipts (`node_id: "review"`, `session_id: None`, `launch_token`, `plan_digest`, `worktree`, `base_commit` (plan base), plus `candidate_commit`, `status: "launching"`, `attempt: 1`, `launcher_invocations: 1`, `launch_requested_at`) before launching; also writes `review.prompt.txt` (mode 0600). Command:
  `[exe, "--bg", "--name", launch_name("review"), "--safe-mode", "--strict-mcp-config", "--mcp-config", '{"mcpServers":{}}', "--tools", "Read,Glob,Grep,Write", "--permission-mode", "dontAsk", "--allowedTools", f"Write(//{completion_path})", "--add-dir", str(self.directory), prompt]`
  where `completion_path` is the absolute path of `<run>/review.completion.json` without its leading slash (Claude permission rules spell absolute paths as `//abs/path`). Environment strips `HERDR_*` like workers. Existing receipt with matching plan digest → reconcile via `locate` (never relaunch), exactly like `run()`. Log to `review.launch.log`; `settle("review")`; update the receipt with `background_id`, `session_id`, `observed_state`, `native_started_at`, `status: "attached_session_available"`; on failure `status: "needs_reconciliation"` + `error`.
- Also record the exact worker prompt: in `run()` write `<node>.prompt.txt` (mode 0600) with the full prompt string right before launching (slice C uses it).
- `attach_panels(sessions, reuse_observers=None)`: after the two worker panes, if `review.interactive.json` exists and the reviewer locates, add a third pane (split the adapter pane `--direction right`, label `Claude: reviewer`, `require_shell`, `attach-one --node review`) and record it under `"review"` in `terminals.json`. New `attach_reviewer_panel(sessions) -> dict`: requires `terminals.json` with ui/adapter and no `review` entry, verifies the reviewer via `locate`, creates the pane the same way, saves the mapping. `attach-one --node review` is accepted (argparse choices `NODES + ("review",)`), validates the receipt/plan digest/locate, chdir to the review worktree, exec `claude attach <id>`.

### 3.3 Review protocol (`automatic.py`)
- Keep `REVIEW_SCHEMA` for print mode but extend finding items with `worker` (enum) and `requirement` (string|null), both required — new print-mode reviews record them too.
- `review_candidate(runtime)`: validate automatic + bundle; read `automatic-review.json` if present:
  - status `succeeded` with matching bundle → return `receipt["review"]` (unchanged behaviour);
  - status `running` and `transport == "native"` → resume: `wait_review` (the reviewer kept running while the controller was away);
  - anything else → `RuntimeError("Prior reviewer invocation needs reconciliation; no automatic relaunch")` (unchanged).
  Otherwise create `review-worktree` at the candidate commit and `review.diff` exactly as today, then dispatch on `reviewer_transport(plan)`: `_review_print(...)` (existing code, moved) or `_review_native(...)`.
- `_review_native`: `launch_token = str(uuid4())`; receipt `automatic-review.json` = `{transport: "native", launch_token, bundle_sha256, candidate_commit, patch_sha256, status: "launching"}` (no session_id yet). Prompt = the existing review prompt text plus the completion-file protocol: it names `<run>/review.completion.json`, shows an example JSON built from `contracts/workflow/reviewCompletion.schema.json` with the run's real `run_id`, `launch_token`, `bundle_sha256`, `candidate_commit`, explains `worker` (`ui|adapter|both|none`) and `requirement` (a verbatim quote from the worker's task text in plan.json under `nodes.<worker>.task`, or null), says the file is the only allowed write, must be written atomically (temporary name then rename is not possible with Write; instead: write it once, as the last action, then end the turn), and that a human may type in this terminal. Then `runtime.launch_reviewer(prompt, launch_token, candidate_commit)` (see 3.4), update the receipt with `session_id`, `background_id`, `status: "running"`, and call `wait_review(runtime)`.
- `wait_review(runtime, *, clock=time.time, sleep=time.sleep) -> dict` mirrors `wait_handoffs`: deadline = `review.interactive.json["launch_requested_at"] + review_timeout_seconds` (`RuntimeError("Reviewer deadline exhausted; no second reviewer is launched")`); each 2 s poll: `locate("review")` must find the row (`"Native reviewer missing; reconciliation required"`), state `blocked` → `RuntimeError`; when state in `{idle, done}` and the completion file exists → `read_review_completion(runtime)`.
- `read_review_completion(runtime) -> dict`: refuse symlinks/non-files/>262144 bytes; parse JSON; `jsonschema.validate` against `contracts/workflow/reviewCompletion.schema.json` (use `verification.validate_schema("reviewCompletion", item)` — it resolves the contracts dir); bind `run_id`, `node_id == "review"`, `launch_token == receipt launch_token`, `bundle_sha256 == current bundle digest`, `candidate_commit == bundle candidate`; a violation is `RuntimeError("Stale or foreign review completion signal")` → fail closed (no relaunch). Returns the decision dict `{verdict, findings}`.
- Acceptance in `_review_native` after `wait_review`: re-check reviewer identity (`locate` row `sessionId` == receipt `session_id` and not equal to either worker session id from the bundle snapshots), worktree unchanged (`rev-parse HEAD == candidate`, clean), bundle digest and `review.diff` hash unchanged; build `review = {run_id, bundle_sha256, candidate_commit, reviewer: session_id, independent: True, verdict, findings}`; write `review.json` regardless of verdict; if verdict != approved or any P0/P1 not resolved → receipt `status: "blocked"`, stop the reviewer, `RuntimeError("Independent reviewer blocked the candidate")`; else `runtime.validate_review(review)`, receipt `status: "succeeded"`, `review`, `accepted_at`, stop the reviewer (`runtime.stop_reviewer()`), return review. `KeyboardInterrupt` during the wait: leave the receipt at `running`, do NOT stop the reviewer, emit event `review` / `interrupted` with the resume note, re-raise. Deadline, blocked session, invalid file: receipt `blocked` + error, stop the reviewer, raise.
- Print mode keeps its current flow but also writes `review.json` on a blocked verdict (with `verdict: "blocked"`) before raising, and records `accepted_at` on success.

### 3.4 Pipeline (`pipeline.py`)
- `Pipeline.launch_reviewer(prompt, launch_token, candidate_commit) -> dict`: events `review`/`running` "Launching the native reviewer session", calls `self.sessions.run_reviewer(...)`, on success event `review`/`interactive` `f"Reviewer session {session_id} launched; awaiting review.completion.json"`, then if `terminals.json` exists and `HERDR_ENV == "1"` tries `attach_reviewer_panel(self.sessions)` and records `review`/`running` "Reviewer pane attached" or "Reviewer pane not attached: <reason>" (never fails the review because of the pane).
- Generalise `stop_workers`: extract `stop_session(node)` (same identity re-check, stop, termination proof, `<node>.stop.json`) and keep `stop_workers()` = loop over NODES + the final "restarted" check + `freeze`/`stopped` event. Add `stop_reviewer()` = `stop_session("review")` + event `review`/`stopped`.
- `validate_review(review, require_approved=True)`: finding keys must be exactly `{severity, message, disposition}` optionally plus `worker` and/or `requirement`, values validated when present (`worker` in `{ui, adapter, both, none}`, `requirement` a non-empty string or None). `require_approved=False` accepts `verdict: "blocked"` (used by export) but still enforces identity and shape.
- New CLI action `export <run>`: takes `run_lock`, builds a lightweight runtime (`ExportRuntime`: `directory`, validated `plan`, `policy`) WITHOUT constructing `InteractiveSessions` (so a copied run directory exports too), refuses when `plan.json` fails `validate_automatic` (when automatic) / policy digest check, or when `review.json` exists and fails `validate_review(..., require_approved=False)` against `review-bundle.json`'s run_id/candidate_commit/file digest (do NOT recheck packet hashes here; the adapter re-verifies packets itself). Opens `pipeline.sqlite`, reads the checkpoint state with `build_pipeline(saver, runtime).get_state(config)` (it never invokes), then `export_state(runtime, state)`; prints the export version and path. Launches nothing.
- `report()` unchanged apart from export_state's new sections.
- The review node in `build_pipeline` is unchanged in shape (it already calls `review_candidate` in automatic mode).

## 4. Workstream S: server adapter

Owned paths: `server/**`, `config/projects.example.json`. Read `contracts/projects/v1.ts` and section 2 first.

- `server/projects.ts`: extend `exportSchema` (versions, `review`, `inputs` strict sub-schemas as in section 2, both `.nullable().optional()`); `LoadedRun` gains `review: ReviewResult | null` and `inputs: RunInputs | null` (projected lazily or eagerly, your call, but never trust `values`). Projection per section 2 (redaction, truncation, `requirement_found_in`, diff artifact). `projectSnapshot`: the `review` node gets `session_id = review.reviewer_session_id` and `result_uri = <run route>/reviews/<attempt>` when the export has a review section (status logic unchanged: task error → failed, evidence → succeeded …). Old exports without the section: `session_id`/`result_uri` stay null.
- Artifact route: a run-level registry beside packet artifacts: when the review section has `diff`, the artifact id `patch-review-<sha12>` resolves to `<run>/review.diff`, read bounded (`artifactByteLimit`), hash-verified, served `text/plain; charset=utf-8`, inline, with the same nosniff/CSP headers. Mismatch → `ARTIFACT_HASH_MISMATCH`; missing → `ARTIFACT_UNAVAILABLE`; ids that match neither registry → `ARTIFACT_NOT_FOUND`.
- `server/projectRoutes.ts`: `GET /:project_id/workflows/:workflow_id/runs/:run_id/reviews/:attempt` → `conform(schemas.reviewResult, ...)` after `validateReviewResult`; 404 `REVIEW_NOT_FOUND` when the run has no review section or the attempt is not the recorded one; `GET .../runs/:run_id/inputs` → `conform(schemas.runInputs, ...)` after `validateRunInputs`; 404 `INPUTS_NOT_FOUND` when absent. Both routes get the 405 treatment for other methods. Error messages never contain paths.
- `server/projects.test.ts`: extend `writeRun` to accept `review`/`inputs` sections and an export `version`; tests for: review served with redaction (a finding message and a requirement quote containing an absolute path under the temp root come back with `<path>`), `requirement_found_in` computed only from verbatim matches (a quote found in the ui task → `['ui']`; a paraphrase → `[]`; null requirement → `[]`), diff artifact served and hash-checked and bounded, blocked review served with verdict blocked while the node projects `failed` (task error) and the run `failed`, legacy 1.0.0 export → 404 `REVIEW_NOT_FOUND`/`INPUTS_NOT_FOUND` and detail still 200 with `session_id`/`result_uri` null, 1.1.0 export (review, no inputs) loads, manual transport passes through the operator identity, inputs projection (task truncation at 65536 chars with marker, prompt null passthrough, timestamps normalised to Z, `stop.confirmed_at`, `launch_node_id`), malformed sections → 500 `RUN_STORAGE_INVALID` without paths, every new payload conforms to the committed schemas and cross-field validators, 405/HEAD on the new routes, nothing written into the run root.
- `config/projects.example.json`: unchanged unless you need to; do not embed private paths.

### 5.2 Review node (slice B) in `NodeDetail.tsx` (or a new `ReviewDetail.tsx`)
