## Acceptance

- **Eligibility** (§5): a player may claim while holding all four types, inside the treasure circle (a content-defined radius around the final island's claim point), stopped, not protected and not reserved for a duel. Starting a claim ends that player's protection first (§6).
- **The channel**: holding interact for 10 seconds completes the claim. Only one channel is active at a time; a second eligible player must wait. Moving, losing eligibility (a lost type), disconnecting or entering a duel resets progress to zero.
- **Completion**: completing commits the winner once and freezes all match outcomes. Inputs arriving after a resolved win cannot cancel it.
- **Same-tick ordering** (§5): each tick processes accepted encounter reservations before advancing claim channels. When several players begin claiming on the same tick, the closest to the claim point wins, then the lowest stable player id. The order players appear in the input never matters.
- **Deadline** (§2): a claim that completes on the deadline tick is processed before the timeout. A match that reaches the deadline without a winner ends with no winner. A duel still running at the deadline is reported as ending without theft (an event for the caller).
- **Tests**:
  - scripted unit tests for every rule above;
  - a symmetry test showing that reordering or relabelling the players gives the same outcome under the ordering rules;
  - seeded random tick sequences showing that at most one winner is ever committed and that the state hashes identically on replay.
- `docs/claim.md` (about a page): the state, the order of operations within a tick, and the events.
- `npm ci` then `npm run typecheck`, `npm run test:unit`, `npm run test:integration` and `npm run build` pass from a clean checkout, and the purity test covers the new directories.
