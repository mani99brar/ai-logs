## Findings to fix (settled after design challenge attempt 1)

Make order independence **true by construction**, then prove it. Each step builds its lead decisions in three phases:
1. **Gather.** Collect every trigger into a set keyed by **(player, type)**, whatever order the triggers arrive in: losses, journal replacements, pending types from a boundary, targeted requests.
2. **Decide.** Decide each (player, type) entry from the older snapshot. Sort its candidate sectors by a stable key, and draw the sector from a key derived from (seed, snapshot tick, playerId, type), or from the shared generator consumed in sorted (player, type) order. Each player gets at most one sighting message per step, listing its types in the fixed type order.
3. **Answer.** Answer targeted requests **grouped by (player, type)** and sorted by `requestId`:
   - `covered` (not charged) if a free trigger already put that player's type in this step's message, or a free rumor for that type in this step;
   - otherwise `sighting` or `rumor` for the first request of that (player, type), and `covered` for the rest;
   - when nothing can be delivered for that (player, type) (for example capped), every request gets the same non-charged result (`capped` or `none`).

   The caller charges only `rumor` and `sighting`. **Two different players' requests never affect each other.**
