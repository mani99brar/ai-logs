# Task: duel

## Goal

Build the deterministic 1v1 duel simulation of §7 and §8 as pure code: two fighters with the Duelist kit in one single-plane arena, stepped at 60 Hz from per-frame inputs, with snapshots that restore and replay exactly. This is the core that the combat spike (`duel-online`) will put online, and that the match room will later host as a duel object (§14). No rendering and no networking.

## Context

- Read `docs/spec.md` §7 (fighting system), §8 (controls and frame budgets), §15 ("Authoritative prediction policy": snapshots, restore, replay), §14 ("Match and duel boundaries") and §19 ("Combat determinism"). §9 describes the Duelist kit; §10's Haki abilities are deferred (see `decisions.md`).
- Read `docs/architecture.md` and the existing pure packages: `packages/simulation` (integer state, `hashState`, the seeded generator in `random.ts`, `fixed.ts`), `packages/content` (`frameBudgets.ts` already holds §8's baseline table with a zod validator) and `tests/unit/purity.test.ts`, which also scans any new directory under the pure packages.
- The verifier runs `npm ci`, then `npm run typecheck`, `npm run test:unit`, `npm run test:integration` and `npm run build` (which ends with `scripts/smoke-build.ts`). It reads test counts from Vitest's summary; `tests/reporters/testSummary.ts` also prints them.
- Another feature (`world-sea`) runs at the same time on the rest of the repository. Stay inside your owned paths so the two merge cleanly.

## Constraints

- Owned paths only: `packages/simulation/src/duel`, `packages/content/src/moves`, `packages/test-tools/src/replay`, the three packages' `package.json` (only to add the subpath exports below) and `docs/duel.md`. Do not edit any existing source file, barrel `index.ts`, tsconfig, root file or `docs/architecture.md`.
- Expose the new code through subpath exports that follow the existing pattern (the `@pirate-sea-race/source` condition first, then `types` and `default` into `dist/`): `@pirate-sea-race/simulation/duel`, `@pirate-sea-race/content/moves`, `@pirate-sea-race/test-tools/replay`.
- Pure and integer, like the rest of `packages/simulation`: no Phaser, Colyseus, DOM, timers, wall-clock time, `Math.random` or floating-point transcendental `Math` functions. Every number in the duel state is a safe integer, so `hashState` covers it.
- The duel step is a function of (config, state, two inputs) that returns a new state and never mutates its input. Randomness, if any, comes from a seeded generator kept in the duel state.
- Out of scope: rendering, networking, rooms, protocol messages, fruit kits, Haki abilities, world integration, theft.

## Acceptance

- Duel rules from §7, covered by unit tests that drive the step with scripted input logs (one test per rule unless a rule is trivially shared):
  - one round, 60-second clock (3,600 frames), 1,000 health each; timeout → higher health wins; equal health → 10-second overtime, then compare, and an exact tie is a draw;
  - both simultaneous lethal hits → draw; a KO on the final round frame beats the timeout; both fighters' hits for a frame are evaluated before a KO is declared, independent of player order;
  - walk, crouch, jump, forward dash and backdash; fighters auto-face each other and stay inside the arena walls;
  - standing guard blocks highs and mids; crouching guard blocks lows, avoids highs and loses to mids; holding back guards and down-back guards low;
  - throws beat guard and have a 10-frame escape window; a throw escape is available to both players;
  - stamina: 100 max; dash costs 20; blocking a light costs 10, a heavy 25 and a special 20; regenerates 20 per second after one second without spending or blocking; a guard break staggers 30 frames and restores 30 stamina;
  - damage: jab 45, committed heavies and specials 100–150; combo scaling 100, 80, 65, 50 and 40 percent; the fifth damaging hit forces a non-juggleable recovery;
  - a 4-frame input buffer; both horizontal directions together are neutral (§8).
- Move data in `packages/content/src/moves`: the Duelist's normals (light/jab, heavy mid, low sweep, launcher, anti-air, throw) and its two specials (advancing thrust, counter slash), each with startup, active and recovery frames, integer hitboxes and hurtboxes, damage, hitstun, blockstun, guard level (high, mid, low, unguardable) and stamina cost. The jab, heavy mid, low sweep and throw match §8's baseline table. A zod validator rejects impossible data (non-positive startup or active frames, block advantage beyond active + recovery, hitboxes with no area, unknown move references), with unit tests.
- Frame advantage: a unit test shows the heavy mid is −12 on block, and that a jab started on the first frame the defender can act lands before the heavy's recovery ends (a punish).
- Determinism and rollback: the same initial state and input log give the same `hashState` after 3,600 frames; a one-input change gives a different hash; restoring a snapshot taken at frame N and replaying the logged inputs from N gives the same hash as the uninterrupted run.
- `packages/test-tools/src/replay`: a replay runner that loads an input log (a documented JSON format), runs it through the duel step and returns the final state and hash; it is used by at least the determinism tests.
- `docs/duel.md` (at most a page and a half): the state shape, the step's order of operations within a frame, the units, and how snapshot, restore and replay are meant to be used by the netcode.
- `npm ci` then `npm run typecheck`, `npm run test:unit`, `npm run test:integration` and `npm run build` pass from a clean checkout, and the purity test covers the new directories.

# Decisions: duel-core

From the operator session of 2026-09-24 (slice planning after the skeleton merged into `main`). These are the recommended defaults; rerun `/workflow-grill duel-core` before launch to revise them.

## Decisions

- Scope is the pure duel simulation only (slice 1 of the plan). Networking, the arena client and the duel room are the next feature, `duel-online`, which builds against this feature's API from `main`. The API therefore has to be usable without changes: a step function, a snapshot that is plain data, and a replay runner.
- One lane (`duel`). Duel rules and move data are too coupled to split, and a split lane would fail its isolated typecheck against the other's types.
- Only the Duelist kit. Fruit kits (§9) come with the content slice; the Duelist's two specials are the advancing thrust and the counter slash.
- Haki abilities (§10: Armament, Observation parry, Resolve finisher) and the Haki meter are deferred. The spike's exit (§18: guard, punish, throw, simultaneous hit, reconnect) doesn't need them, and they add balance work before the core is proven.
- Units: integer sub-pixels, 16 sub-pixels per arena pixel. Positions, velocities, gravity and hitboxes are integers; hitboxes and hurtboxes are axis-aligned rectangles relative to the fighter's origin and facing.
- The code lives in new directories behind subpath exports (`@pirate-sea-race/simulation/duel`, `@pirate-sea-race/content/moves`, `@pirate-sea-race/test-tools/replay`), so this feature edits no existing file. `world-sea` runs at the same time on the rest of the repository, and the two branches must merge without conflicts.
- No browser check: nothing is rendered. The policy's checks are typecheck, unit, integration (unchanged, to prove nothing broke) and build (its smoke step proves the new subpath exports resolve from `dist/`).

## Assumptions

- The arena is one plane with two walls and a floor; its width is content data. There's no stage hazard and no ring-out.
- A duel input per player per frame is a button bit field (light, heavy, special one, special two, dash) plus integer horizontal and vertical directions in {-1, 0, 1}, already as §8 maps keys. Keyboard mapping is client work.
- Frame data for moves outside §8's table (launcher, anti-air, the two specials) is the worker's choice within §7's ranges, documented in the move data.
- `hashState` from `packages/simulation` is reused for duel state, which also holds the duel's own frame counter and generator state if it needs one.
- The duel starts both fighters at fixed positions, facing each other, with full health and stamina, as §6 requires ("no free opening hit").

## Deferred

- Haki meter and abilities (§10), fruit kits (§9), focus scrolls.
- Networking, prediction and reconciliation, the input delay policy, reconnect: `duel-online`.
- Rendering, animation, the duel HUD and control remapping: `duel-online`.
- Hosting the duel inside `MatchRoom`, reservations, transitions and theft: `encounters-theft`.
